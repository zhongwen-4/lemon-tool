# 界面里「标签 + 值」的多行块：标签列别设固定宽度，值用 weight(1f) + marquee

SUMMARY: 2026-09-29 给「检查历史」条目卡做「名称 / 路径 / 时间 / 标签」四行时，标签列**没有**用
`Modifier.width(38.dp)` 那种固定宽度 —— 中文标签都是两个字，宽度天然一致，一个 `padding(end = 10.dp)`
就够；**固定宽度是按默认字号量出来的，系统字号一放大（fontScale 1.5+）就把标签裁掉**，而且只在放大字号
的那台机器上看得出。值那一侧用 `Modifier.weight(1f)` 吃掉剩余宽度，配 `basicMarquee()` + `maxLines = 1` +
`softWrap = false`（marquee 生效的前提），长模块名自己滚动、不会把右列挤掉。右列（状态文案 + 箭头）
是值列在同一个 `Row` 里的兄弟，用 `padding(start = 16.dp)` 隔开，别塞进值列里。

READ WHEN: before 做「每行一个标签 + 值」的列表/卡片（条目卡、日志详情、自绘设置项、信息卡），
或用户反馈「大字号下标签被裁」「长文本把右边那列挤没了」时。

RECHECK WHEN: MiuiX / Compose 改了 Text 的测量行为，或本项目换成别的行组件之后。

---

## 为什么

- 固定列宽是按「默认字号」量出来的数字：字号一放大，两个字的中文就超过那个宽度，文字被裁一半；
  模拟器默认字号下看不出来，只有用户那台机器会露馅。
- 中文两字标签（名称 / 路径 / 时间 / 标签）本身宽度相同，`padding(end = …)` 之后值列自然对齐，
  不需要表格式的固定列宽 —— 要对称就该靠「同样的字」而不是「同样的 dp」。
- 值的截断用 `basicMarquee()` 而不是省略号：日志类界面里用户常常要看全路径 / 全模块名。
- 值列必须 `weight(1f)`，否则长内容会把右列（状态文案 + 箭头）顶出屏幕。
